# Лабораторна робота №1 — Сучасні технології баз даних

## Система управління бібліотекою з додатковими послугами

**Дисципліна:** Сучасні технології баз даних  
**Університет:** Київський національний університет імені Тараса Шевченка  
**Факультет:** Комп'ютерних наук та кібернетики  
**Група:** ТТП-31  
**Рік:** 2026

---

## 1. Мета роботи

Мета лабораторної роботи — спроєктувати та реалізувати реляційну базу даних для системи управління бібліотекою з додатковими послугами.

Основні завдання:

1. Розробити базу даних із не менше ніж 15 сутностями.
2. Реалізувати Soft Delete та аудит змін для щонайменше 6 сутностей.
3. Реалізувати базу даних у PostgreSQL.
4. Створити процедури, функції, тригери та представлення.
5. Створити не менше 6 індексів щонайменше двох типів.
6. Реалізувати доступ до бази даних із C# за допомогою Repository та Unit of Work.

## 3. Опис предметної області

Система призначена для обліку бібліотечних ресурсів та управління додатковими послугами.

Реалізовано облік:

- користувачів, читачів і працівників;
- посад і філій бібліотеки;
- книг, авторів, жанрів та видавництв;
- фізичних примірників книг;
- видач та повернень;
- бронювань;
- штрафів;
- додаткових послуг і замовлень.

## 5. Обмеження цілісності та індекси

Для забезпечення коректності даних реалізовано:

- PRIMARY KEY;
- FOREIGN KEY;
- UNIQUE;
- NOT NULL;
- CHECK.

CHECK-обмеження використовуються для контролю допустимих статусів, ролей, кількостей, цін та інших значень.

У базі створено більше шести індексів.

Використано прості та складені, унікальні та неунікальні індекси.

Приклади:

```sql
CREATE UNIQUE INDEX ux_users_email
ON users(email);

CREATE INDEX ix_authors_last_name
ON authors(last_name);

CREATE INDEX ix_books_title
ON books(title);

CREATE UNIQUE INDEX ux_book_copies_barcode
ON book_copies(barcode);

CREATE INDEX ix_book_copies_book_branch
ON book_copies(book_id, branch_id);

CREATE INDEX ix_loans_reader_returned
ON loans(reader_id, returned_at);
```

Індекси використовуються для прискорення пошуку та забезпечення унікальності окремих значень.

## 6. Soft Delete та аудит змін

Для шести сутностей реалізовано логічне видалення:

- readers;
- branches;
- employees;
- authors;
- books;
- services.

Замість фізичного видалення запису встановлюється:

```text
is_deleted = true
```

Поле `deleted_at` містить дату й час логічного видалення.

Для аудиту змін використовуються:

- `updated_at` — дата останньої зміни;
- `updated_by_user_id` — ідентифікатор користувача, який виконав зміну.

Для автоматичного оновлення полів реалізовано тригерну функцію `set_audit_fields()`.

До шести таблиць підключено відповідні BEFORE UPDATE тригери.

Також створено окремі процедури Soft Delete.

## 7. Збережені процедури та функції

Для реалізації бізнес-логіки бібліотеки використовуються процедури PostgreSQL.

### Видача книги

Процедура `borrow_book` створює запис про видачу книги.

Перед виконанням перевіряються:

- активність читача;
- активність працівника;
- існування примірника;
- доступність примірника;
- коректність дати повернення.

Після успішної видачі статус примірника автоматично змінюється на `borrowed`.

### Повернення книги

Процедура `return_book` заповнює інформацію про повернення.

Відповідний тригер змінює статус примірника на `available`.

### Користувацькі функції

Реалізовано функції:

- `calculate_overdue_fine()` — обчислення штрафу за прострочення;
- `get_available_copies_count()` — визначення кількості доступних примірників.

## 8. Тригери

У базі даних реалізовано:

- 6 тригерів аудиту змін;
- тригер перевірки умов видачі;
- тригер зміни статусу примірника після видачі;
- тригер зміни статусу після повернення.

Тригери забезпечують автоматичне виконання визначеної бізнес-логіки та підтримання узгодженості даних.

## 10. C# — Repository та Unit of Work

Для взаємодії з PostgreSQL створено консольний застосунок на C#/.NET.

Використано бібліотеку Npgsql.

### Repository

Реалізовано два репозиторії:

**BookRepository**

Отримує інформацію про доступні книги через представлення `v_available_books`.

**LoanRepository**

Забезпечує отримання активних видач та виклик процедур `borrow_book` і `return_book`.

### Unit of Work

Unit of Work використовує спільне підключення до PostgreSQL для роботи репозиторіїв.

Реалізовано керування транзакціями:

- BeginTransaction;
- Commit;
- Rollback.

Для перевірки транзакцій створюється тестова видача книги, після чого виконується ROLLBACK.

Після відкату всі зміни скасовуються, а книга залишається доступною.

## 12. Встановлення та запуск

### Необхідне програмне забезпечення

- .NET SDK 10;
- PostgreSQL;
- Visual Studio або інше середовище для .NET;
- pgAdmin (для перегляду та керування БД).

### 12.1. Підготовка PostgreSQL

Створити базу даних:

```text
Library_management
```

Відкрити pgAdmin та виконати SQL-скрипт:

```text
Database/LibraryDb_full.sql
```

Скрипт створює таблиці, обмеження, індекси, процедури, функції, тригери, представлення та тестові дані.

### 12.2. Налаштування підключення

Рядок підключення зберігається в .NET User Secrets.

У папці C#-проєкту виконати:

```powershell
dotnet user-secrets set "ConnectionStrings:PostgreSQL" "Host=localhost;Port=5432;Database=Library_management;Username=postgres;Password=YOUR_PASSWORD"
```

Замість `YOUR_PASSWORD` потрібно вказати пароль локального користувача PostgreSQL.

Для роботи команди проєкт повинен мати налаштований `UserSecretsId`.

Паролі не зберігаються у вихідному коді та не публікуються в репозиторії.

### 12.3. Запуск

Перейти в папку `LibraryManagementApp` і виконати:

```powershell
dotnet restore
dotnet build
dotnet run
```

Або відкрити проєкт у Visual Studio та запустити через Ctrl + F5.
